# Compilar / Building

**Español** · [English](#english)

Compilar **no necesita el juego**. Compilas `BLACK.exe` (el port); el código del propio juego (`Black.dll`) lo genera el ejecutable la primera vez que arranca, a partir de la copia del juego de quien lo usa. Para probar tu compilación, instala el juego con el instalador o pon tu `.iso` junto a `BLACK.exe`.

## Qué necesitas

| Herramienta | Notas |
|---|---|
| Windows 10/11 x64 | |
| Visual Studio 2022 o Build Tools (2022 o más reciente) con **Desktop development with C++** y el SDK de Windows | `release.bat` usa `d3dcompiler_47.dll` del SDK |
| **Clang/LLVM** | Componente "C++ Clang tools for Windows" de Visual Studio, o `winget install LLVM.LLVM` (se probó con 23.1.5) |
| **CMake ≥ 3.25 y Ninja** | Vienen con "C++ CMake tools for Windows" |
| Git | |
| 7-Zip (`7z` en el PATH) e Inno Setup 6 | Solo para `release.bat` (zip e instalador): `winget install JRSoftware.InnoSetup` |
| Python 3 | Solo para `tools/refresh_prebuilt.py` (ver más abajo) |

`build.bat` busca Visual Studio con `vswhere`, detecta lo que falta y ofrece instalarlo.

## 1. Clonar

```
git clone https://github.com/<tu-usuario>/BLACK-PC.git
cd BLACK-PC
```

El SDK [XboxXBE-Recomp](https://github.com/TGP482/XboxXBE-Recomp) se usa así: si existe `sdk\` en el repo o una carpeta hermana `..\XboxXBE-Recomp`, se usa esa; si no, CMake lo descarga **fijado al commit `91146ff`** (`CMakeLists.txt`). El SDK más reciente cambió firmas (p. ej. `Backend::Copy`) y no compila con este código sin adaptarlo. CMake además **parchea in situ** varios archivos del SDK (rutas de guardado nativas, ruta UTF-8 de ajustes, fuentes por idioma): por eso el SDK aparece "modificado" en git y es normal.

## 2. Compilar

```
build.bat
```

- Usa el preset `release` (Ninja + clang, `-march=x86-64-v2`). `build.bat debug` da logs completos.
- Construye **solo el ejecutable**, a partir de `prebuilt/` (ver [prebuilt/README.md](../prebuilt/README.md)). Tarda unos minutos.
- Resultado: `out\build\release\BLACK.exe`.

Manual (consola de desarrollador x64): `cmake --preset release` y `cmake --build out\build\release`.

## 3. Ejecutar

`out\build\release\BLACK.exe` busca el juego en su propia carpeta: los archivos extraídos (`default.xbe` del USA, `GlobData.bin`, `chars`, `data`, `export`, `language`, `levels`, `sound`, `videos`) o un `.iso` (USA o Europa; el de Europa se convierte al arrancar). Lo más cómodo:

```
out\build\release\BLACK.exe --setup "C:\ruta\juego.iso"
```

extrae el disco junto al ejecutable, construye `Black.dll` (unos minutos) y termina. Después se ejecuta `BLACK.exe` normalmente. El registro está en `logs\black.log`.

## 4. Pruebas

```
cmake -S tests -B out\tests -G Ninja -DCMAKE_CXX_COMPILER=clang++ -DCMAKE_BUILD_TYPE=Release
cmake --build out\tests
ctest --test-dir out\tests --output-on-failure
```

Cubren subtítulos y almacenamiento de guardados; no necesitan el juego.

## 5. Paquetes de release e instalador

```
release.bat
```

Genera `BLACK-PC.zip` y, si Inno Setup está instalado, `BLACK-PC-Setup.exe`. Ver [RELEASING.md](RELEASING.md) e [INSTALLER.md](INSTALLER.md).

## 6. Regenerar `prebuilt/` (solo mantenedores)

Solo si cambias `config/game.toml` o los hooks `X86_FUNC` de `src/`. Necesita tu copia del juego, una vez:

```
python tools/refresh_prebuilt.py "C:\ruta\juego.iso"
```

Acepta el `.iso` (USA o Europa) o un `default.xbe`; hace la recompilación completa del juego, copia lo necesario a `prebuilt/` y borra lo temporal.

## Problemas frecuentes

| Síntoma | Causa / solución |
|---|---|
| Aviso "otra versión" al arrancar | El juego no es la edición USA ni la de Europa |
| `BLACK.exe` desaparece / se cierra | Windows Defender (falso positivo heurístico en ejecutables sin firma): excluye `out\build\release` |
| Errores de firma (`Copy`, `override`) | Usas un SDK más nuevo que `91146ff` |
| `d3dcompiler_47.dll not found` | Falta el Windows SDK |
| Errores de símbolos sin resolver al enlazar | `prebuilt/` desactualizado: ver la sección 6 |

# English

Building **does not need the game**. You build `BLACK.exe` (the port); the game's own code (`Black.dll`) is generated by the executable on its first start, from the user's copy of the game. To try your build, install the game with the installer or put your `.iso` beside `BLACK.exe`.

## Requirements

Windows 10/11 x64 · Visual Studio 2022 / Build Tools with **Desktop development with C++** and the Windows SDK · **Clang/LLVM** (VS component or `winget install LLVM.LLVM`, tested with 23.1.5) · **CMake ≥ 3.25 and Ninja** · Git · 7-Zip on the PATH and Inno Setup 6 (only for `release.bat`: `winget install JRSoftware.InnoSetup`) · Python 3 (only for `tools/refresh_prebuilt.py`). `build.bat` finds Visual Studio with `vswhere` and offers to install what is missing.

## 1. Clone

`git clone` the repo. The [XboxXBE-Recomp](https://github.com/TGP482/XboxXBE-Recomp) SDK is taken from `sdk\` in the repo, a sibling `..\XboxXBE-Recomp`, or downloaded **pinned to commit `91146ff`**. Newer SDK commits changed signatures (e.g. `Backend::Copy`) and need code changes. CMake also **patches some SDK files in place** (native save paths, UTF-8 settings path, per-language fonts), so the SDK shows as modified in git: that is expected.

## 2. Build

`build.bat` (preset `release`; `build.bat debug` for full logs). It builds **the executable only**, from `prebuilt/` ([prebuilt/README.md](../prebuilt/README.md)), in a few minutes. Output: `out\build\release\BLACK.exe`. Manual: `cmake --preset release` then `cmake --build out\build\release`.

## 3. Run

`BLACK.exe` looks for the game in its own folder: extracted files (the USA `default.xbe`, `GlobData.bin`, `chars`, `data`, `export`, `language`, `levels`, `sound`, `videos`) or an `.iso` (USA or Europe; Europe is converted at start-up). The easiest way: `out\build\release\BLACK.exe --setup "C:\path\game.iso"` extracts the disc beside the executable, builds `Black.dll` (a few minutes) and exits; then run `BLACK.exe` as usual. The log is `logs\black.log`.

## 4. Tests

The commands above (`cmake -S tests ...`, `ctest`). They cover subtitles and save storage and need no game.

## 5. Release packages and installer

`release.bat` writes `BLACK-PC.zip` and, with Inno Setup installed, `BLACK-PC-Setup.exe`. See [RELEASING.md](RELEASING.md) and [INSTALLER.md](INSTALLER.md).

## 6. Refreshing `prebuilt/` (maintainers only)

Only when you change `config/game.toml` or the `X86_FUNC` hooks in `src/`. It needs your copy of the game, once: `python tools/refresh_prebuilt.py "C:\path\game.iso"` (an `.iso`, USA or Europe, or a `default.xbe`). It does the full recompile of the game, copies what is needed into `prebuilt/` and removes the temporary files.

## Troubleshooting

"Another release" warning → the game is neither the USA nor the Europe release. `BLACK.exe` vanishes → Windows Defender heuristic false positive on unsigned executables: exclude `out\build\release`. Signature errors → SDK newer than `91146ff`. `d3dcompiler_47.dll not found` → install the Windows SDK. Unresolved symbols at link → `prebuilt/` is stale (section 6).
